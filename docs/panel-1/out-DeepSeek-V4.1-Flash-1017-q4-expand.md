**Three expansions that fit the substrate:**

1. **Per-stream "why did you alert me?" replay / correction UI.** Month 2 is when the 0.9-precision auto-demotion starts firing and users get silent feeds they don't understand. The ledger already holds structured state and the trust spec already depends on one-tap corrections — but there's no surface to *see* the evidence (which tiles, which embed delta, which judge call) behind an event. Without it, corrections are blind taps and the precision number is unauditable. Fix: ledger gains an event-evidence pointer; serve plane renders a 10-second scrub of the gated tiles plus the reflex-rank order. Cheap, because it's replay of already-stored artifacts, not new perception.

2. **Scheduled/contextual budget profiles ("away," "night," "guest").** A household will demand the box behave differently when nobody's home vs. movie night vs. in-laws visiting — and the current "plain language knobs" are static. This fits directly: budget is already metered in embed-seconds per stream and global, and the yield ladder already defines priority ordering. Add named budget profiles as a ledger record and a scheduler lane; the attention plane swaps the active profile. Failure mode to name: profile thrash (switching every 5 min) starves backfill — require hysteresis (min dwell 30 min) and let the 5-pass overnight ladder only run under the "away/night" profile.

3. **Cross-stream correlation rules the user writes in plain language ("tell me if the front door and the driveway both change within 2 minutes").** The "what changed" feed is per-stream; a household's actual questions are conjunctive (package = door + porch cam + maybe doorbell audio). The ledger is structured text, so a small rule grammar over ledger fields is a natural fit, and it rides the existing budget rather than adding perception. Refuse the temptation to make this a general automation engine (see below). Failure mode: rule explosion producing correlated false events that blow the 1/day/stream target — cap active rules (say 8) and count rule-fired events against the *weakest* contributing stream's precision budget.

**One tempting expansion to refuse:**

**Arbitrary third-party app/plugin execution on the box (a "home stream app store").** It breaks the trust model outright — the whole point is one household, one tenant, measured budgets, and a yield ladder that protects the owner's own work; untrusted plugins can't be metered in embed-seconds, can't be demoted by the 0.9 precision rule, and turn the single-box-no-failover v1 into an unattributable failure surface. If extensibility is demanded, expose a read-only ledger query API instead.
